# Shiori — F04.1: Sidebar UX Polish

## Context

F04 — Production UI Foundation & Responsive Layouts — has been implemented, committed and pushed to `main`.

An independent review of the published source and screenshots identified two specific UX issues:

1. The Sidebar focus ring can be visually obscured by the hover background of an adjacent navigation item.
2. Status is incorrectly grouped with Home in the primary navigation, although it is a technical diagnostic page.

We also agreed that the current Home page is temporary and will eventually become the learner's Dashboard.

**This is a narrowly scoped implementation task. Do not perform a general frontend refactor.**

## 1. Fix Sidebar focus ring overlap

### Problem

When a sidebar navigation item has keyboard focus and the mouse hovers over the adjacent item, the focused item's outline is partially obscured.

For example:

- Home receives focus using Tab.
- The mouse hovers over Status.
- Status's hover background visually overlaps Home's focus ring.

This is a genuine UI accessibility issue.

### Requirements

Inspect the current:

- AppSidebar.
- SidebarMenu.
- SidebarMenuButton.
- Focus ring classes.
- Hover and active styles.
- Element stacking and clipping behavior.

Implement the smallest appropriate fix.

Consider:

- Adding a small vertical gap between navigation items, such as Tailwind `gap-1`.
- Correcting the stacking order of focused items if spacing alone is insufficient.
- Ensuring ancestors do not clip the focus indicator.

Important:

- Prefer styling through the consuming AppSidebar component.
- Do not modify generated shadcn primitives unless absolutely necessary.
- Do not remove or weaken the existing focus ring.
- Do not introduce custom focus management.
- Preserve active, hover, disabled and keyboard states.
- Keep touch targets accessible.
- Apply consistent spacing across navigation groups.

### Verification

Check:

1. Focus Home using Tab, then hover Status.
2. Focus Status, then hover Home.
3. Repeat with Account and Security.
4. Test the currently active route.
5. Test Light and Dark themes.
6. Test keyboard navigation and pointer interaction.
7. Confirm that the full focus indicator remains visible.

Use actual browser verification where possible.

Do not rely exclusively on jsdom for visual focus-ring behavior.

If authenticated browser access is unavailable, use the existing real Sidebar Storybook story to reproduce the interaction and report that limitation.

Do not request credentials or create a new authentication workflow for this small task.

## 2. Reorganize navigation groups

### Current structure

```text
Home
Status

Settings
  Account
  Security
```

### Desired structure

```text
Home

Settings
  Account
  Security

System
  Status
```

### Requirements

- Move Status into a separate `System` navigation group.
- Position System after Settings.
- Keep Home in the primary navigation.
- Keep the existing `/status` route unchanged.
- Preserve existing titles, icons and access requirements.
- Continue deriving navigation from the typed route registry.
- Do not introduce duplicated navigation arrays.
- Do not create a generic navigation management framework.
- Do not introduce placeholder routes or pages.

### Navigation ordering

Inspect how route definitions and `getNavigation()` determine navigation group order.

If the order can be corrected safely by reorganizing existing route declarations, prefer that.

However, do not compromise route matching or the catch-all route merely to control navigation order.

If explicit group ordering is necessary, implement the smallest strongly typed solution.

Avoid unnecessary sorting systems, configuration factories or additional abstractions.

### Tests

Update or add focused tests confirming:

- Home remains in the primary navigation.
- Account and Security belong to Settings.
- Status belongs to System.
- Group order is Main → Settings → System.
- Existing route matching and route access remain unchanged.
- Active navigation states still work.
- Mobile navigation uses the same metadata.
