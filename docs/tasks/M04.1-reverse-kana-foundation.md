# Shiori - M04.1: Reverse Kana Practice Domain & Persistence Foundation

## Goal

Prepare the domain model, question planning, per-Kana result semantics and persistence for Romaji → Kana practice and for rounds that mix both directions, without changing the practice UI. M04 (Extended Kana Practice) adds three mutually exclusive practice modes per script page: Kana → Romaji (existing), Romaji → Kana, and Both directions. There is no combined Hiragana/Katakana mode.

Later phases (not authorized by this document): M04.2 reverse-practice UI and IME handling; M04.3 practice mode selector and mixed-direction sessions in the UI; M04.4 statistics presentation, regression coverage and audit.

## Scope

In scope:

1. Concrete question directions (`kana-to-romaji`, `romaji-to-kana`) and session modes (the two directions plus `both`) in `@shiori/kana`.
2. Reverse reading groups derived from the catalog, unordered multi-Kana answer matching and question planning for every mode.
3. A session model where one question (card) can hold several per-Kana results, with the M03 first-attempt, hint, correction and skip semantics per Kana.
4. Persistence identity `(user_id, round_id, question_index, kana_id)`, a forward-only migration, direction-aware validation and statistics.
5. Storage, queue and synchronization compatibility with M03 data.

Out of scope: the Romaji → Kana screen, IME handling, the mode selector, Statistics tab changes, cross-tab locking, a generic training engine.

## Decisions

| Topic                 | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Direction vs. mode    | `KanaDirection` is the direction of one question and of every persisted result. `KanaPracticeMode = KanaDirection \| 'both'` is a session setting only; it is never persisted on a result.                                                                                                                                                                                                                                                                                                                                              |
| Card vs. result       | A question (card) is one displayed prompt; the configured question count is always the number of cards. A Romaji → Kana card expects every Kana of its reading and produces one result per expected Kana, all with the same round id and question index.                                                                                                                                                                                                                                                                                |
| Reading groups        | Grouped per script by the canonical displayed reading (`romaji`), never by accepted alternatives. Id `<script>/<romaji>` (`hiragana/ji`), deliberately unlike a Kana id (`hiragana:zi`). Ambiguous groups in the catalog: ji (じ, ぢ) and zu (ず, づ) in both scripts; no yōon group is ambiguous (ぢゃ/ぢゅ/ぢょ are not in the catalog); お (`o`) and を (`wo`) stay apart although を accepts `o`. 102 groups per script; member count is not assumed.                                                                               |
| Selection             | Selecting a Kana selects nothing else. A Romaji → Kana card for a selected Kana expects the whole reading (selecting only じ asks `ji` and expects じ and ぢ, and both receive results). Selecting both じ and ぢ gives one `ji` unit, not two.                                                                                                                                                                                                                                                                                         |
| Planning              | The M03.2.2 balanced scheduler moved unchanged to `@shiori/kana` (`buildQuestionOrder`, now generic over string keys). Units: one per selected Kana (Kana → Romaji), one per reading group (Romaji → Kana), both lists for `both`. `planQuestions` balances units, so `both` is balanced per unit; directions are roughly even (exactly even per full cycle when no selected Kana shares its reading).                                                                                                                                  |
| Matching              | `matchKanaAnswers`: answers are trimmed and NFKC-normalized (half-width katakana and decomposed dakuten match; Hiragana never matches Katakana). Each expected Kana is matched at most once; the set of correct Kana does not depend on input order. Unmatched answers are assigned to the unmatched Kana in input order and recorded as their incorrect first answers. A yōon form is one answer.                                                                                                                                      |
| First evaluation      | Check does nothing until every field holds a non-empty answer of at most 32 characters, so an incomplete form creates no result.                                                                                                                                                                                                                                                                                                                                                                                                        |
| Per-Kana finalization | At the first check each Kana gets `correct` or `incorrect`. A correct Kana is final at once (sent while the others are still being corrected). A later check marks each newly matched incorrect Kana `corrected`; a correction never creates a new result. A hint before the first check sets `hintUsed` on every Kana of the card; a hint while correcting sets it only on unresolved Kana. Skip before the first check records `skipped` for every expected Kana; Skip while correcting finalizes the unresolved ones as `incorrect`. |
| Persistence key       | Primary key `(user_id, round_id, question_index, kana_id)`. A partial unique index `kana_attempt_kana_to_romaji_question_idx (user_id, round_id, question_index) WHERE direction = 'kana-to-romaji'` keeps the M03 rule of one result per Kana → Romaji question, so a forward retry with another Kana is still a conflict.                                                                                                                                                                                                             |
| Validation            | Per result: Kana → Romaji as in M03; Romaji → Kana compares the normalized answer with the expected Kana form (`correct` must match, `incorrect` must be non-empty and not match). Within one batch, results sharing a round id and question index must all be Romaji → Kana, distinct Kana, one script and one reading. Results of one card may arrive in different batches; that cross-batch grouping is not re-checked (no anti-cheat).                                                                                              |
| Conflicts             | 409 `conflicts` entries now carry `kanaId` (additive). The server inserts in key order so concurrent batches with the same results in another order do not deadlock.                                                                                                                                                                                                                                                                                                                                                                    |
| Statistics            | `GET /api/kana-progress` accepts an optional `direction` (default `kana-to-romaji`, so existing calls are unchanged). Counts are results per Kana in that direction, not cards. M03 rows are Kana → Romaji. No UI change.                                                                                                                                                                                                                                                                                                               |
| Session storage       | Version 2 records (`order` of question objects, `results` per card, `inputs` per expected Kana, `mode`). Version 1 records are upgraded on read and written back as version 2 on the next write.                                                                                                                                                                                                                                                                                                                                        |
| Pending queue         | Format unchanged (`version: 1`); `direction` accepts both values; entries are identified by round id, question index and Kana id. M03 queues are read and sent unchanged.                                                                                                                                                                                                                                                                                                                                                               |
