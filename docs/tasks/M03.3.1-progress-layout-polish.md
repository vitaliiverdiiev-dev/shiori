# Shiori — M03.3.1: Progress Correctness & Responsive Layout Polish

## Goal

Fix issues found while testing M03.3 in the authenticated app, without redesigning the application:

1. “With hint” stayed zero although hints were used.
2. A correct answer could be lost when the user left during the 400 ms success delay.
3. The Kana selection page used a narrow column and became very tall on desktop.
4. The application header scrolled away and showed no page title.
5. The Kana pages had an unnecessary introductory paragraph.

## Decisions

| Topic               | Decision                                                                                                                                                                                                                                                                   |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hint column         | Not a persistence or aggregation bug (see `docs/03-architecture.md` → “Hint column”). The statistics keep their semantics; the labels become “Correct, no hint” / “Correct with hint”, and the legend explains that Incorrect includes hinted corrections. No data repair. |
| Finalization timing | A question is queued as soon as its record cannot change: a right first answer or a successful correction at submission, a skip when the round moves on. The 400 ms delay controls presentation only.                                                                      |
| Progress table      | Was raw semantic HTML; now the official shadcn `Table` primitive. No TanStack Table: no sorting, filtering or pagination is needed.                                                                                                                                        |
| Kana layout         | Container-query grid: 1 → 2 → 3 columns by available content width; Progress full width below; content column widened to `max-w-7xl`.                                                                                                                                      |
| Header              | Sticky; shows the route registry `title` as the page's single `<h1>`. No Portal: titles are static. `FocusLayout` stays without a header.                                                                                                                                  |
| Toolbar             | Sticks directly below the header through `--app-header-height`; a scroll margin keeps focused controls clear of both sticky bars.                                                                                                                                          |

Out of scope: sorting, filtering or pagination of statistics, new statistics, Kanji/vocabulary/reverse practice, unrelated backend changes.
